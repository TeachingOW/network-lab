Parsing in the shared buffer

void feed(Conn* c, char* p, size_t n) {
  if (c->in_len || c->sending) {
    stash(c, p, n);        // keep a copy
    if (!c->sending) run(c);
    return;
  }
  c->in = p;               // parse in place
  c->in_cap = c->in_len = n;
  process(*c, w);
  size_t left = c->in_len;
  c->in = nullptr;
  c->in_cap = c->in_len = 0;
  if (left) stash(c, p, left);
  after_process(c);
}

p is the kernel’s shared buffer. In the common case the connection simply points at it, the request is handled, and the pointer is cleared. Nothing is copied.

left is what remains of an incomplete request. Only that is copied to a private buffer.

The first branch covers a connection that already holds input or is mid-reply: its bytes must be kept, because p goes back to the kernel on return.

feed is called for every chunk of data the kernel delivers, with a pointer into one of the shared buffers and a length. The parser, process, works on whatever the connection’s in pointer refers to, so the trick is to aim that pointer at the shared buffer for the length of one call. process handles every complete request it finds and moves any incomplete remainder to the front. Afterwards the connection lets go of the buffer. If something was left over, a request whose body has not all arrived, stash copies just that part into a heap buffer sized for the whole request, and later chunks are appended to it. The top branch is the other case where a copy is unavoidable: the connection already has saved input, or a reply is still being sent and the output buffer cannot be appended to, so the new bytes are saved for after the send. The caller returns the shared buffer to the kernel as soon as feed returns, which is why nothing may keep pointing into it.
