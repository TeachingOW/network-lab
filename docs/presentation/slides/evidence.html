To compare event loops without the database in the way, the reference was rebuilt with SQLite, its B-tree read paths, the group commit and JWT removed, serving bulkapi’s API from an in-memory table. This table is a same-session rerun against both current bulkapi backends, each limited to one thread. bulkapi is far ahead with 16 connections, because the reference waits up to 2 milliseconds per batch, and on pipelined requests, because the reference answers one request per connection per batch. At 256 connections they are level. The reference is ahead at 2,000 connections, at about 14 to 15 microseconds of CPU per request against 20 to 25 for uring-ms in this run, and on bulk get, at about 27 to 35 microseconds against 42 to 45. Its bulk get path differs from ours in three ways: a store with no locks, JSON escaping 16 bytes at a time, and a response written once. The third is now done and did not close the gap, which points at the store and the escaping.
