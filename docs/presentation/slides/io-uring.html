What io_uring is

io_uring is Linux’s interface for asynchronous input and output. The program and the kernel share two queues in memory, so they can exchange many requests without a system call for each one.

Submission queue

The program writes what it wants done: accept a connection, receive, send.

Completion queue

The kernel writes the result of each operation here when it finishes.

One call for many

A single system call hands over every queued request and collects every finished one.

With the older epoll interface every read and every send is its own system call: about twice the kernel time per request here

Some background before the optimisations. A server spends most of its time asking the kernel to do things: accept a connection, read from a socket, write to one. Each of those is normally a system call, and a system call is expensive compared with ordinary code. io_uring, added to Linux in 2019, replaces most of those calls with two ring-shaped queues that live in memory shared between the program and the kernel. The program puts requests on the submission queue, the kernel puts results on the completion queue, and one call, io_uring_enter, moves a whole batch in each direction. bulkapi also has an epoll backend, the older interface, where the kernel only reports which sockets are ready and the program then makes one call per read and one per send. On the same workloads it cost about twice the kernel time per request.
