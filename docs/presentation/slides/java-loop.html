for (;;) {
  enter(true);       // the one native call
  int head = cqHead.getInt(0);
  int tail = (int) INT.getAcquire(cqTail, 0);
  while (head != tail) {

    head++;
    Conn c = conns.get((int) (ud >>> OP_BITS));

  }
  INT.setRelease(cqHead, 0, head);
}

cqes is the kernel’s completion queue, mapped into Java as a direct ByteBuffer. Java reads results straight out of shared memory.

enter() is the only call that leaves Java: one per turn, however many requests it covers.

The tag is an index, not a pointer: Java has no addresses, so user_data holds the connection’s position in a list.

Abridged from UringBackend.java · liburing sets the ring up through a small JNI shim, native/uring_jni.c

6 / 30

Java cannot call io_uring directly on JDK 11, so the usual approach is a native call for every operation, which is slow because crossing from Java into native code has a fixed cost. This port avoids that. A small C shim uses liburing once to create the ring and returns the memory addresses of the two queues. Java wraps those addresses as direct byte buffers and from then on reads completions and writes submissions itself, exactly as the C++ code does through pointers. getAcquire and setRelease are the Java equivalents of the atomic loads and stores the kernel expects on the queue’s head and tail. The single remaining native call is io_uring_enter, once per loop turn. The tag on each operation is the connection’s index in a list shifted left by three bits, with the operation type in the low bits, because Java objects have no stable address to store.
