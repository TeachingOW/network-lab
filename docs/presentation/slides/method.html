Method

How each change was measured

Same answers

A 34-line probe is run before and after. Responses must be byte-identical, including split packets, pipelining and a 20 MB upload.

CPU per request

One server thread, so server CPU time divided by requests is meaningful. Old and new binaries run in alternating rounds.

Honest about noise

The same binary varies by up to 2x between runs here. A difference under about 1.5x is not treated as real.

Intel i5-1145G7, 4 cores, WSL2; load generator on the same machine

3 / 30

Three rules were applied to every change. First, correctness: the same probe of 34 response lines is run against the old and the new build and must match byte for byte. Second, the metric: with a single server thread, CPU time per request is a cleaner signal than throughput, because the load generator shares the four cores. Third, noise: on this laptop the same binary can swing by a factor of two between runs, so small differences are reported as no measurable change rather than as wins.
