Optimisation 2 · implemented

No buffer per connection

What changed. A request is parsed in place in the shared receive buffer, with no copy. A private buffer exists only while a request is incomplete, and is freed after.

Result. Memory per idle connection fell 14-fold. Speed is unchanged.

4.54 KB

Process memory growth, 20,000 connections idle after one request each · --backend uring-ms

10 / 30

The multishot backend already received into shared buffers, but it copied every request into a 16 kilobyte buffer owned by the connection. Now the request is parsed directly in the shared buffer. Only two cases still need a private buffer: a request that has not fully arrived, and input that arrives while a reply is being sent. That buffer is freed as soon as it is drained. Output buffers are borrowed from a per-worker pool only while a reply exists. Measured with 20,000 connections that each made one request and then sat idle, memory per connection went from 4.54 kilobytes to 0.30. The single-shot backend still holds 4.33 kilobytes. An earlier estimate of 16 kilobytes per connection was wrong: only the touched part of each buffer stays in memory.
